# GitHub workflow checklist

Use the project to practice the whole GitHub workflow, not just commits. Check things off as you really do them.

## Set up the repository

- [ ] Create the repo `branchline` (public) and push this code
- [ ] Replace `YOUR-USERNAME` and `YOUR NAME` in `index.html`, `README.md`, and `LICENSE`
- [ ] Add a repository description and topics (`git`, `education`, `javascript`, `github-pages`)
- [ ] Turn on GitHub Pages with Source set to GitHub Actions
- [ ] Add a branch protection rule for `main` that requires a pull request and passing CI

## Work like a team (even if you are the only one)

- [ ] Create labels: `bug`, `enhancement`, `good first issue`, `documentation`
- [ ] Open issues for the roadmap ideas below
- [ ] Make every change on a branch and merge it with a pull request
- [ ] Link pull requests to issues with `Closes #n`
- [ ] Create a Project board (To do, In progress, Done) and add the issues
- [ ] Tag a release: `v1.0.0`, with release notes

## Invite others

- [ ] Ask a classmate to review a pull request
- [ ] Label two issues `good first issue` and invite a friend to fix one
- [ ] Add the live link to your school's CS club page or newsletter

## Roadmap ideas to turn into issues

1. Support `git stash` and `git stash pop`
2. Support `git reset --soft` and `--hard` with a warning about lost work
3. Support `git tag`
4. Add a `.gitignore` mission
5. Add a "pull request" mission that simulates review on a fake GitHub page
6. Add Spanish translations of the missions
7. Add a dark theme
8. Let learners share a link to their commit map
9. Add a mission about undoing a mistake with `git restore`
10. Improve merge conflict detection for inserted lines
